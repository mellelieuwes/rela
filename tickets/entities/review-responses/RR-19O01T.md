title: 'Design review: A stale or out-of-order pull rolls back theirs fields'
finding: 'Pull records RemoteUpdatedAt but never compares it (design:240-243). Suppose an agent retries a stale payload, or two agent runs overlap and the older snapshot lands last. For every theirs field, R_old ≠ B_new, so R_old is written and the entity goes back to the older external state. The stale pull succeeds and records base := R_old, so the next correct pull fixes it, but meanwhile the regression was written and audited as a sync. Fix: refuse (with an error) or no-op a pull whose remoteUpdatedAt is earlier than the stored RemoteUpdatedAt, unless `--force` is given. Make remoteUpdatedAt required for pull. Add a table case.'
severity: significant
resolution: '`--remote-updated-at` is required for pull; a pull older than the stored RemoteUpdatedAt fails with ErrStalePull unless --force. Covered in service and CLI tests.'
status: addressed
