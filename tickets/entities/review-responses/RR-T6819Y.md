title: Browser truthiness differs from Lua for selection
finding: conditions.ts truthy() treats '' and 0 as falsy. If logical returns operands and 'or' falls through on truthy(), form.opt or 'x' yields 'x' for an empty string in the browser but '' in the Go engine. The plan did not define fall-through or error handling for the browser.
severity: significant
resolution: 'Revised during implementation: the browser engine is untyped and cannot tell selection from logic. and/or now return an operand (Lua structure) but keep the browser''s existing truthiness and fail-safe operands, so every boolean condition evaluates exactly as before. In selection '''' and 0 therefore also fall through; for forms that is desirable because an empty field is ''''. The divergence from predicate (nil-only fall-through) is documented in conditions.ts and docs/data-entry.md. Only the browser evaluates visible_when/required_when, so no server/browser disagreement on one condition arises. Vitest cases cover '''' and 0, and boolean logic with failing operands.'
status: addressed
