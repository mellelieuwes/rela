title: 'Code review: Readonly body editor and entity-page checkboxes still write an owned body'
finding: 'This patch adds the `readonly` prop to MilkdownEditor via `editable: () => !props.readonly`. That only gates ProseMirror''s own edit handlers. The task-list checkbox''s DOM click listener calls `view.dispatch(setNodeMarkup…)` without checking `view.editable` (taskListItem.ts:97-115). A click in a `content_writable:false` form therefore flips the box, marks the editor dirty, emits `update:modelValue`, and autosave sends a content PATCH. The server answers 422, but the ticked box stays on screen. [INFERENCE] The link tooltip''s Edit/Unlink buttons stay live in readonly mode as well (useLinkUI submit/unlink dispatch unconditionally). On the entity page, `handleCheckboxToggle` (EntityDetail.vue:663-700) and `canAccept` (531-533) ignore `content_writable`: they apply the change optimistically, schedule a PATCH, and never revert after the 422. DynamicForm.twins.test.ts stubs MarkdownEditor, so it only checks that the prop is passed through. No test mounts the real editor readonly. Fix: in the checkbox listener, add `if (!view.editable) { this.checkbox.checked = this.node.attrs.checked === true; return }`. Add `if (props.readonly) return` at the top of the markdownUpdated listener and of flush(), and hide LinkTooltip/LinkDialog when readonly. In EntityDetail, refuse the toggle and the accept when `entry.content_writable === false`. Add a real MilkdownEditor readonly test: a checkbox click emits nothing.'
severity: significant
resolution: 'Read-only editor: checkbox clicks no-op when the view is not editable, the update listener and flush emit nothing, link tooltip/dialog are hidden; the entity page refuses checkbox toggles and suggestion accepts when content_writable is false. Tests: real MilkdownEditor readonly specs, EntityDetail.twins and EntityDetail.accept specs (mutation-checked).'
