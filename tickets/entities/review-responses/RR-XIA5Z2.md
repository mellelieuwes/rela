title: 'Code review: Make the service''s twin read-modify-write atomic; a CLI pull can undo a rename'
finding: 'The flock covers each individual Store call, but Pull, Pushed, markGone and Pending all do `Get`/`List` → read the entity → `store.Update(tw)` with the twin they read earlier (service.go:342/394, 430/489, 498-511; the Pending loop calls markGone on list items). `filetwins.Update` is unconditional and follows `tw.Target.ID`: when that differs from the file on disk it re-indexes the twin to the stale id (file.go:207-228). Concrete interleaving: the agent''s `rela twin pending` lists twin T (target SC-1). rela-server renames SC-1 to SC-9, and its alias hook runs `Retarget` (T now targets SC-9). The CLI then calls `GetEntityVersion(SC-1)`, gets not-found, and `markGone(T)` writes T back with `Target.ID=SC-1, state=gone`, undoing the retarget. Result: SC-9 has no live twin, so its theirs fields are unguarded. The agent sees `gone` and, per GUIDE-twins, propagates a delete to the external item that still mirrors a live entity. The same lost update lets a concurrent `twin gone` be overwritten by a pull, or a pull''s base be overwritten by a racing `pushed`. The window in Pending grows with the number of twins, because each entity is read in sequence after the List. Fix: make the store''s Update conditional. Either add a revision field and `ErrStale` (checked under the flock, with the service re-reading and retrying), or expose `Modify(ctx, system, id, func(Twin) (Twin, error))` that runs the service''s decision under the lock. At minimum, `Update` must never change `Target.ID` (only Retarget re-targets) and markGone must re-read inside the lock. Add a twinstest cross-instance case: Retarget in A between Get and Update in B must not revert the target.'
severity: significant
resolution: 'twins.Store gains Modify(ctx, system, id, fn), run under the store lock (flock + mutex in filetwins). Update/Modify can never re-target a twin (CheckReplace → ErrStale); the service writes the entity outside the lock and commits bookkeeping through Modify, re-checking target, liveness and that no other sync landed meanwhile. Tests: twinstest RunModifyTests / RunModifyRefusalTests incl. cross-instance ''Retarget in A between Get and Modify in B does not revert the target''; service TestRenameDuringSync and TestPull_OvertakenWhileWriting.'
status: addressed
